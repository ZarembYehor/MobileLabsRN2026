## Основний функціонал

### Авторизація та безпека
* **Реєстрація та Вхід:** Екрани для автентифікації користувачів.
* **Глобальний стан:** Використання `Context API` для збереження стану користувача.
* **Захищені маршрути:** Автоматичне перенаправлення неавторизованих користувачів на екран входу. Доступ до каталогу мають лише авторизовані користувачі.

### Каталог товарів
* **Головний екран:** Відображення списку товарів у вигляді зручної сітки за допомогою FlatList.
* **Картки товарів:** Кожна картка містить фотографію, назву та ціну товару.
* **Динамічні деталі:** При натисканні на товар відкривається екран із детальною інформацією, реалізований через динамічний маршрут `/details/[id]`.

### Навігація та UI
* **Expo Router:** Сучасна файлова маршрутизація.
* **Обробка помилок:** Кастомний екран `+not-found.tsx` для обробки неіснуючих посилань.
* **Адаптивність:** Інтеграція `react-native-safe-area-context` для коректного відображення контенту на iOS та статус-баром на Android.

## 📝 Контрольні запитання та відповіді

**1. Яким чином за допомогою Expo Router реалізується перенаправлення неавторизованого користувача?**
В Expo Router для цього використовується декларативний компонент `<Redirect>`. Перевірка стану авторизації зазвичай відбувається у файлі макета захищеної групи маршрутів. Якщо локальна змінна чи стан контексту вказує на те, що користувач не авторизований, компонент макета замість дочірніх екранів повертає `<Redirect href="/login" />`, що миттєво перенаправляє потік програми на сторінку входу.

**2. У чому полягає різниця між використанням компонента `<Link>` та метода `router.push()`?**
Компонент `<Link>` є декларативним підходом і використовується безпосередньо у JSX-розмітці. Він ідеально підходить для створення кнопок навігації або посилань у тексті, покращуючи доступність. Натомість `router.push()` — це імперативний метод, який викликається всередині JavaScript-функцій. Його доцільно використовувати тоді, коли перехід на інший екран має відбутися як результат певної логічної дії.

**3. Як працюють динамічні маршрути в Expo Router і як отримати передані параметри?**
Динамічні маршрути створюються шляхом використання квадратних дужок у назві файлу або папки, наприклад, `[id].tsx`. Це вказує роутеру, що ця частина URL-адреси є змінною. Коли користувач переходить за посиланням на кшталт `/details/123`, Expo Router відкриває файл `[id].tsx`. Щоб отримати значення `123` всередині компонента, використовується спеціальний хук `useLocalSearchParams()`, який повертає об'єкт із переданими параметрами.

**4. Чому стан авторизації доцільно зберігати у глобальному контексті (React Context), а не в локальному стані компонента?**
Стан авторизації є фундаментальними даними, які необхідні багатьом компонентам на різних рівнях ієрархії додатка: роутеру, навігаційній панелі, екранам профілю тощо. Якщо зберігати цей стан локально, доведеться передавати його через пропси на всі інші рівні, що робить код заплутаним і важким для підтримки. Глобальний контекст дозволяє будь-якому компоненту додатку отримати миттєвий доступ до стану авторизації та методів входу/виходу через хук `useContext`.

**5. Для чого використовуються групи маршрутів `(folderName)` і як вони впливають на URL-адресу?**
Групи маршрутів створюються за допомогою дужок у назві папки, наприклад, `(app)` або `(auth)`. Їхнє головне завдання — логічно згрупувати екрани та застосувати до них спільний макет (`_layout.tsx`) без зміни самої URL-адреси. Наприклад, файл розміщений за шляхом `app/(auth)/login.tsx`, буде доступний в додатку за простим маршрутом `/login`, а не `/auth/login`. Це дозволяє створювати складні структури з різними правилами навігації та дизайнами, зберігаючи при цьому чисті та короткі шляхи.
